The comparer runs only the original; before it the copy's periodic work and idle continuation run dry (a copy of the record, a text buffer of their own, no widget/redraw/save/box call). With no command (id 0) the original's menu bar record (without the refresh time) and its answer must match the prediction: 'menubar_handle_command (menu bar record)'. With a command of fixed answer (screen openers -4, 0x42d -11, 0x3fb -4/-11, 0x402 0/-4, the arrows -2/-3/0) the answer is checked: 'menubar_handle_command (menu bar, command ...)'. Not compared: a network game, a box answer to dispatch (0xb77c84), the match Continue 0x3e8, an outcome that needs running (a save, a box, a screen), a run in which the clock crossed a threshold the decisions read (the header's refresh time, the holiday stamp + 2 s, a change of second).
Mutations (mutacoes.py, for a session of Lucas): the "You Have News" status kind 2 (caught on the frame news arrive); the header's phase not flipped (caught within a second on any screen with the team menu bar).

Defects of the original (kept): after a failed save from the save dialog with the disk full or the no memory box the typed path is never freed (a leak); 0x3fd with no menu bar record would write 0 at address 0xee. Note: a failed auto save sets the last save date to today (the next try waits the interval; it avoids retrying every frame).
