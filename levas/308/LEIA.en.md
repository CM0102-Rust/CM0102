**Result** (`cadeia.txt`):
- **Mutations (22):** 20 caught. `mwg3_goleiro_qualquer` escaped: MEASURED ESCAPE: the mutation accepts any player with goalkeeper >= 15 as the template goalkeeper, instead of exactly 20. In `staff.dat` (the player table, the first 30,000 records, where the template is drawn from) there are **2,747 players with goalkeeper 20 and only 9 between 15 and 19**. Each template goalkeeper draw thus has a ~0.3% chance of hitting one of the 9 and changing the result; in both runs (career and comparison until 2001-08-20) none did. The comparer `compare_create_virtual_player` compares the whole copied record and would catch it if one were hit. To close it with a mutation that always catches, replace `== 20` with `!= 20`. `mwg4_conta_qualquer` escaped: ESCAPE EXPLAINED BY ARGUMENT: the mutation counts the human manager rows whose classification is not 0 instead of equal to 1. The 16 rows are classified 0 (free), 1 (in use) and 5 (being created, only while the manager is created). In the automatic holiday career the only human is already created when the count runs, so there are only rows 0 and 1, and `!= 0` gives the same as `== 1`. The value of each row at the moment of the count was not measured; a mutation replacing `== 1` with `== 0` would be caught. (gap in `PENDENCIAS.en.md`)
