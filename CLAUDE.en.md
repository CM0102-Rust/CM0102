## Decisions in force (do not change without Lucas)

- **Rust**, coming in routine by routine: a DLL loaded by the original exe, with hooks on the rewritten functions. The game stays playable the whole time and each routine is compared with the original.
- **Identical interface above all:** modernizations (resolution, fonts, scaling) only after the rewritten screen matches the original pixel for pixel.
- **Determinized original (2026-10-15):** original routines that read a local variable with no value (stack garbage that changes with the mode) get, in every mode, a hook that zeroes the stack below the entry (`ZERADAS` in `motor.rs`, `desvios::desviar_zerando`). The careers' reference is the original with these zeroings; the Rust copies use zero. Each new zeroing is proven (probe) and documented. **Zero only when zero is a value the game also produces** (the 0x84be20 one, batch 212, led to an artificial path and was undone). **Switched-off routines (2026-10-23):** when a routine's hook changes the stack residue an original uses later, the hook stays off in every mode (`DESLIGADAS` in `motor.rs`; the copy stays in the code) until the copy reproduces the residue. The proof of each such change includes the broad career (8 leagues, Rust = original).
- **Batches of 9 routines (2026-10-21; 3 before, since 10/15):** each batch joins up to 3 queue items of the same kind (screens or simulation), 3 routines each, and runs a single chain (the chain time is almost all fixed); a divergence is located by each routine's comparator (or `SEM_ROTINAS`); an item that causes trouble leaves the batch on its own. To go back to 3: `ITENS_POR_LEVA = 1` in `fila.py`.
- **Working base: `cm0102.exe` (DirectDraw).** That is where the addresses mapped by the community are. `cm0102_GDI.exe` is the reference for the GDI video path.
- **The original exes are never modified.** Fixes go into tool-generated copies (`*-portatil.exe`), which checks the original's MD5 and fails if an expected pattern does not match.
- **Nothing from the game in git:** no exe, no `Data/`, no raw decompiled code. The `CM0102-Rust/CM0102` repository (an organization; formerly `lucastmpacheco/CM0102`) is private.
- `referencias/CM0102Patcher` and `referencias/cm0102-function-map` (function and global names, CC BY 4.0; see `docs/ENDERECOS_COMUNIDADE.en.md`) is a source of addresses and formats; do not copy its code (the tools read the data from there).
- **Working version: native 1920×1080** (`cm0102-1080.exe`, generated by `resolucao.py`). Background pictures turned off in the game settings ("trocar = não") until the video layer fits the pictures to the resolution.
- **The clicks in the game are Lucas's.** I open the game and they drive; diagnosis through the code (disassembly, Windows crash log, `ddraw.log`), not by trial and error clicking.

## Environment

- Python 3 with `pefile`, `capstone`, `psutil`, `Pillow` (installed in the user's Python).
- Addresses always as VA (base 0x400000). In `.text`, `.rdata` and `.data` the file offset is VA − 0x400000.
- Rust: `cd rust && cargo build --release` (output in `target/i686-pc-windows-msvc/release/ddraw.dll`; copy to `jogo/`), `cargo test --release`.
- **Trap:** restoring a `.rs` with `Copy-Item` keeps the old timestamp and cargo does not recompile (the DLL stays stale). After restoring, update the timestamp (`(Get-Item f).LastWriteTime = Get-Date`) or check that "Compiling" appeared.
- Validation of a rewritten routine: `CM_AUTOTESTE=1` (synthetic inputs at game startup, no clicks) and `CM_COMPARAR=1` (during the real game). **Test bench without Lucas:** automatic holiday career (`auto_setup.cfg` with `ON_HOLIDAY=YES`, see `docs/VERSAO_SEM_TELA.md`) + `CM_COMPARAR=1` + `CM_JANELA=960x540`, with backup and restore of `game.cfg`. Prove that the test discriminates with a deliberate mutation before trusting "zero divergences".
- **Machine shared with other heavy sessions (Elifoot):** on 2026-10-06 the PC froze due to a driver leak in the kernel pool (~105 GB), fed by a lot of disk I/O. Heavy tests only through `simular.py`, which uses `engenharia-reversa/laboratorio.py`: shared lock `D:\Sistemas\.laboratorio.lock` (one heavy test at a time across sessions) and memory watchdog (does not run with non-paged pool > 3 GB or free RAM < 4 GB). One game at a time; never several in parallel. `python laboratorio.py` shows the state.
- COM methods are stdcall: each vtable method needs the exact number of arguments, even the unsupported ones.
- **Always windowed (`-windowed`)**, in the shortcut and in the tests; never test in full screen or maximize (it covers Lucas's screen while they use the PC). Whatever can only be seen in full screen, ask them to test.
- **Experiments that may change preferences** (automatic setup, language change...): copy `jogo/game.cfg` before and restore it afterwards. Do not leave `auto_setup.cfg`/`quick_start.cfg` in the game folder. See `docs/VERSAO_SEM_TELA.md`.
- The window opens at the size/state in Lucas's `jogo/janela.cfg` (it may be maximized and cover their screen). **In tests, use `CM_JANELA=960x540`**: fixed size, no maximizing and no writing to `janela.cfg`.
- Lucas sometimes moves the window during tests: an unexpected size change may be them.
- To test the game without disturbing Lucas: open it with `-windowed` and send clicks via `PostMessage` (it does not move their mouse).
